# Результаты проверки версии v4

Проверено 10 сценариев × 100 seed = 1000 реализаций; на каждой выполнены baseline и v3. Все 2000 оценок завершились. Seed 1000–1099 используются во всех сценариях, поэтому при расчёте интервала разницы ошибки повторения объединены по seed. Это синтетическая проверка, а не подтверждение точности на реальных пассажирах.

Общий первичный спрос задавался извне. N=300 в основных сценариях; сценарий низкого спроса использует N=135. Модель: sigma=0.45, prior_strength=0.5, beta_time=beta_qty=0, одна компонента бюджета, fixed_design, без предварительной калибровки. Оба метода получали одинаковые bookings и полную историю offers; passengers использовались после восстановления.

Средняя MAE скрытого спроса по периодам: **16,7636 → 10,0188 места**. Парная разность v3 − baseline: **−6,7448**, bootstrap 95%: **[−7,3680; −6,1384]**. v3 лучше в **77,6%** пар, равна в **3,6%**, хуже в **18,8%**.

Покрытие условных интервалов в среднем **56,44% вместо номинальных 80%**. Эти интервалы фиксируют оценённые параметры и поведенческие предположения; их нельзя трактовать как полную неопределённость. Новый раздел устойчивости показывает чувствительность и повторные оценки, но не обещает исправить покрытие на любых сценариях.

Дополнительно проверены все исследовательские действия через фоновую очередь и формирование HTML/ZIP: native passengers, 8 вариантов чувствительности + 3 бутстрап-повтора, 8 кандидатов калибровки, 4 временных среза, 12 тарифных кандидатов и согласованный комплект с закрытиями продаж.

На отдельном демонстрационном holdout из трёх запусков калибровка улучшила распределение бюджетов, но MAE спроса выросла с 2,80 до 3,33 места. Применение калибровки остаётся явным действием пользователя.

Для native SU1122 прогноз занятых мест по заданным предположениям: D90=38,70, D30=69,20, D14=110,03, D7=113,92 при фактическом итоге 116. Ранние прогнозы существенно слабее поздних; история offers для этих журналов отсутствует.

Полный проверяемый результат: `dist/reports/benchmark.html`. На текущем компьютере полная серия также сохранена в локальной истории. Скрипт `scripts/verify_research.py` воспроизводит интеграционные проверки и формирует отчёты.
