# История предложений offers

Необязательный CSV задаёт **историю действовавших предложений**, включая дни без покупок. Загрузите его в дополнительных настройках вместе с bookings. Для каждого рейса и салона интервалы должны непрерывно покрывать весь горизонт моделирования без перекрытий. Используются полуоткрытые интервалы `[start, end)` в UTC; горизонт включает день вылета. Время конца последнего интервала — начало следующего дня UTC.

Колонки: `flight;cabin;start;end;price;open;available_seats;rbd`. `open` — true/false либо 1/0, `available_seats` — неотрицательное целое, `price` — положительная цена за место для открытых продаж, `rbd` — необязательный код. При изменении цены или доступности начинается новый интервал. Состояние должно соответствовать покупкам, находящимся внутри интервала.

Пример **только формата** (не история предоставленных рейсов):

```csv
flight;cabin;start;end;price;open;available_seats;rbd
SU1122;Y;2027-01-22T00:00:00Z;2027-05-23T00:00:00Z;12000;true;168;R
SU1122;C;2027-01-22T00:00:00Z;2027-05-23T00:00:00Z;36000;true;12;J
```

Постоянные остатки в таком примере — допущение, а не восстановленная история. Для физического ограничения вместимости нужны действительные изменения остатков после покупок и возвратов. Не подставляйте пример вместо неизвестных исторических данных. Без offers приложение использует явно обозначенное приближение по bookings.
